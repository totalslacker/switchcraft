# ADR 005 — Bucket indices encoding

**Status**: Accepted
**Date**: 2026-04-28
**Issue**: #10 (Phase 1: LSM-tree index)

This ADR locks the on-disk wire format for `BucketRecord.indices`
and `BucketRecord.center`. Both are written by `Indexer` in
`Sources/SwitchcraftCore/Indexer/Indexer.swift` and the codecs in
`Sources/SwitchcraftCore/Indexer/IndicesCodec.swift` and
`Sources/SwitchcraftCore/Indexer/LZ4.swift`.

Format changes here invalidate every existing on-disk index. Cite
this ADR in any future PR that changes the layout, the delta-encoding
rule, or the LZ4 framing.

---

## (a) Index pair shape: `(UInt32 chunkID, UInt32 tokenOffset)`

Each entry in `indices` is the 2-tuple Witchcraft calls a `DocPtr`:

- `chunkID`: the `chunk.id` (Switchcraft) / `document.rowid`
  (Witchcraft) the embedding came from.
- `tokenOffset`: 0-based index of the token within that chunk's
  embedding sequence.

Both fields are `UInt32`. `Indexer.add` precondition-checks that the
caller's `Int64 chunkID` fits in `UInt32`. Corpora with more than
2³² (≈ 4.3 B) chunks cannot be indexed.

**Why UInt32?** Matches Witchcraft's 8-byte `DocPtr` exactly so that
future cross-validation fixtures (the project's primary correctness
gate, per CLAUDE.md) bind directly. Alternative considered: `UInt64`
varint deltas — rejected because it breaks Witchcraft parity.

## (b) Wire format for `bucket.indices`

```
inner = first pair as raw [u32 LE major][u32 LE minor]
        + for each subsequent pair:
            [u32 LE deltaMajor][u32 LE deltaMinor]
        where deltaMajor = pair.major &- base.major
              deltaMinor = (deltaMajor == 0)
                            ? pair.minor &- base.minor
                            : pair.minor

bucket.indices = LZ4.compressPrependSize(inner)
```

Subtraction is *wrapping* (`&-` in Swift, `wrapping_sub` in Rust) —
identical to Witchcraft's `compress_keys` (lib.rs lines 282–308).
Decode reverses with wrapping addition; round-tripping holds even
when the deltas underflow.

Pairs within a bucket are written in ascending order by
`(chunkID, tokenOffset)`. The Search pipeline relies on this for
efficient delta scanning.

## (c) `bucket.center` layout

`bucket.center` is `dims * sizeof(Float32)` bytes — `dims` IEEE-754
single-precision floats in **explicit little-endian byte order**.

Encoding by hand (rather than `withUnsafeBytes` raw memory copies)
makes the on-disk format independent of host endianness. Apple
platforms are LE today; the format must outlive that assumption so
fixtures captured on Apple still round-trip on a future big-endian
backend.

## (d) LZ4 framing

`LZ4.compressPrependSize` produces:

```
[u32 LE uncompressed size][raw LZ4 block bytes]
```

This is bit-compatible with `lz4_flex::block::compress_prepend_size`.
Apple's `Compression.framework` `COMPRESSION_LZ4_RAW` is used for
the LZ4 block. The framework refuses to compress incompressible
inputs (returns 0); in that case the encoder falls back to a hand-
rolled all-literals LZ4 sequence, which is valid LZ4 (the last
sequence omits its match part).

**Parity gate**: the *decoder* is the contract. Switchcraft's
`LZ4.decompressPrependSize` must accept any blob produced by
`lz4_flex` (validated by `Tests/Fixtures/lz4/sample-roundtrip.json`).
Switchcraft's encoder need not be byte-identical to `lz4_flex` —
multiple valid LZ4 compressions exist for the same input.

## (e) Endianness

Both `center` and `indices` use *explicit* little-endian encoding:

- `center` writes each `Float32`'s `bitPattern` byte-by-byte as
  `(b0, b1, b2, b3)`.
- `indices` writes each `UInt32` byte-by-byte in the same order.
- LZ4's prepended size header is `[u32 LE]`.

There is no implicit reliance on host endianness via
`withUnsafeBytes` or `Data(bytes:)` raw memory copies, even though
that would compile and run correctly on Apple silicon today.

## (f) Parity fixtures

Two parity fixtures are committed:

- `Tests/Fixtures/lz4/sample-roundtrip.json` — input/output pairs
  produced by Rust `lz4_flex` 0.11.
- `Tests/Fixtures/indices/sample-pairs.json` — `(chunkID,
  tokenOffset)` lists encoded by a port of Witchcraft's
  `compress_keys` against `lz4_flex` 0.11.

Both are exercised by `IndexerLZ4Tests` and `IndexerIndicesCodecTests`.

### Regenerating the fixtures

The fixtures were generated by a tiny throwaway Rust crate
(`/tmp/lz4-fixture-gen/`) that pulls `lz4_flex = "0.11"` and either
calls `compress_prepend_size` directly (LZ4 fixture) or runs a
verbatim port of `compress_keys` from Witchcraft `lib.rs` lines
282–308 (indices fixture). To regenerate:

```bash
mkdir -p /tmp/lz4-fixture-gen/src/bin
# Cargo.toml: depend on lz4_flex = "0.11"
# main.rs:    print LZ4 fixtures (input + compress_prepend_size)
# bin/indices.rs: print indices fixtures (pairs + compress_keys output)
cargo run --release --bin lz4-fixture-gen \
    > Tests/Fixtures/lz4/sample-roundtrip.json
cargo run --release --bin indices \
    > Tests/Fixtures/indices/sample-pairs.json
```

The fixture JSON format is intentionally simple (`{label, *_hex}`)
so it can be inspected and re-generated without committing a Rust
build target into the Swift package.
